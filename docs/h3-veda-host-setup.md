# H3 terminal host setup

`inventory` and `stage` are CPU-only Actions modes. They require the exact current
SceneWorks/inference checkout SHAs, explicit backend and exact named runner. They
do not require a product binary, manifest, corpus directory, complete cache or
future permanent-main pin. The existing read-authority probe verifies the actual
workflow/run/job/runner. These modes skip token generation, builds, product/API
launch, imports, guardian acquisition, campaign execution and media export.
Their job deadline is ten minutes. Neither mode establishes GPU admission.

The default-main registration header must match these five mode choices and all
ten input names before dispatch against the exact feature ref. The four path
inputs are optional at dispatch; prepare/resume/review retain their existing
runtime path/source requirements.

The workflow executes these commands on the selected host:

```sh
node scripts/h3-veda-actions.mjs inventory mlx
node scripts/h3-veda-actions.mjs stage mlx
```

Use `candle_cuda` on an explicitly selected Windows runner. Inventory reads only
the source template's finite cache-root candidates and exact approved snapshot
file paths. It reports Mac platform UUID/Metal model or every Windows GPU
UUID/index, metadata availability and sizes. It never treats a filename, cache
label or matching size as weight-byte verification. The artifact is only
`RUNNER_TEMP/h3-veda-terminal/setup-receipt.json`; no weights or private media are
uploaded. A different cache root needs an explicit source allowlist update,
not a home-directory scan.

Stage makes a fresh inventory, then copies the source-owned 33 synthetic files
without invoking encoders. All 901,110 bytes must match the existing corpus plan
before any write, and again after materialization. The default persistent root
is the observed checkout's sibling `.h3-veda-epic-25140/SHA/RUNNER_NAME`; optional
`run_dir`/`corpus_root` select external owned paths. Existing roots and symlink
ancestors refuse. A supplied cache root must have been observed in the declared
allowlist. It means HF_HOME, with Hub files beneath `CACHE_ROOT/hub`.

Stage writes `manifest.preparation.json`, artifact inventory, owner marker and
stage receipt. The template preserves both backends, 204 model descriptors,
four published Turbo adapters, two styles, all 5,400 named cells and the explicit
catalog refusals. Style-inclusive matrix size is 11,016; optional stress is zero.
All required proof routes remain declared. Styles retain source/header evidence,
without runtime or Michael quality acceptance.

Preparation is deliberately not runnable acceptance. Missing counterpart
physical identity, both real source-built binary attestations, cache payload
verification, permanent-main/pin freeze, actual import IDs and forced-condition
proof setup remain explicit in `preparation.missingBindings` and `unresolved`.
An ambiguous multi-GPU inventory does not select a device. Normal prepare rejects
an unresolved preparation before binary sealing or product import. Source freeze,
durable CPU binary builds, counterpart proof exchange and ordinary product imports
must resolve these bindings before the unchanged guardian can admit a campaign.
