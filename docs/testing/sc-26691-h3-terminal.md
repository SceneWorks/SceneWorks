# H3 fine-tune terminal acceptance preparation (sc-26691)

This is executable **campaign preparation**, not accepted real-weight evidence. Story sc-26691 remains In Progress. No pin, campaign dispatch, model download, feature review, or main merge is performed by these scripts. The existing `h3-veda-*` registration-only workflows remain intentionally untouched. There are no measurement-currency or new runtime-admission gates.

## Execution path

- `node scripts/h3-finetune-terminal.mjs list` prints the complete required inventory: the eight frozen artifact/backend executions, plus backend-local numerical, conditioning, generalization, and lifecycle mechanisms. No filename or precision substitution is allowed. Capability mechanisms may use different *compatible* artifacts, not falsely exercise an unsupported operation on every file.
- Stage a version-1 JSON plan **outside both clean repositories**. `check-plan PLAN` validates its complete inventory without running anything.
- Only after the coordinator confirms the final stationary paired revisions, inference-main merge, and permanent consumer pin: manually dispatch `.github/workflows/h3-finetune-terminal.yml` at the exact SceneWorks ref, supplying the exact pair, one listed case, staged plan, external output, and exact runner name. Authorization defaults to false. MLX uses the existing `rw-chroma` route and requires `nax-macos-2`; CUDA uses the existing Windows `cuda,real-weights` route. Do not use another physical device to work around an actual task restriction.
- The job checks out both exact sources, validates the permanent pin and inference-main ancestry, streams input hashes before and after execution, captures actual subprocess results, and rechecks clean source identities. Artifact cases retrieve only the frozen HF revision's metadata (`blobs=true`) during the authorized job and compare the actual checkpoint digest with its published LFS SHA-256, retaining `source-catalog.json`; internally consistent stock-weight receipts cannot impersonate a frozen artifact. It does not provision weights, choose substitute checkpoints, claim a GPU reservation, or acquire global tokens/locks.
- `run-case PLAN CASE SW_ROOT INFERENCE_ROOT` is Actions-only. Each command is an argv array (no shell interpolation); `H3_CASE_DIR`, `H3_CASE_ID`, `H3_INFERENCE_ROOT`, and `H3_TIMEOUT_SECONDS` are provided. Commands must use task-owned API/worker instances and disposable application state, never a user's running app/shared mutable cache. Native builds/fixtures also run only in explicit Actions.
- `verify PLAN` rehashes every source input and retained evidence file, redecodes AV and redoes comparisons; missing cases are failures. This command records delivery evidence, **not** an automatic merge, Shortcut transition, or statement that a reviewer validated the linked CI/tracker snapshots.

## Plan contract

Top-level fields: `version:1`, full `sceneworks` and `inference` commit IDs, `source` exactly as printed by `list`, `output` (absolute existing external directory), `responsibleTask:"sc-26691"`, `nextAuthorizedAction` (explicit recovery action), and `cases` (the entire `list` inventory).

Each case retains its listed `id/backend/group/artifact` and adds:

- `command`: source-bound executable argv; `timeoutSeconds`: integer 1–7200; `evidence`: case-relative JSON output name.
- `inputs`: actual staged files `{path:absolute,sha256:actualHex64,role,artifact?}`. The original contracted checkpoint must have `role:"checkpoint"` and its exact frozen artifact name. Include actual component/adapter and executable reference inputs. Obtain SHA-256 by streaming actual file contents; do not invent hashes or use metadata/tree stamps.
- `loadHostBudgetBytes`, `loadDeviceBudgetBytes`: separately declared campaign limits. Never sum device allocations and RSS on unified memory. These limits do not alter runtime admission.
- Numerical cases: `referenceRevision` (full pinned executable reference revision), `referenceCommand` (argv), `referenceOutput` (relative JSON numeric array), `tolerance:{atol,rtol}`. The reference executes separately **before** the native candidate. Its output is hashed before the candidate and cannot be silently replaced. Declare justified tolerances before execution; scale changes fail even if cosine similarity would pass.
- Capability cases: `controlStream:"video"|"audio"`, `minimumControlDelta` (declared normalized-RGB or float-PCM RMSE threshold). Use audio for audio-reference discrimination. The harness fully decodes both AV streams, then itself compares a bounded 8-second, 16×16/1-fps RGB or mono/8-kHz PCM probe. The producer cannot pass by claiming a delta or changing only container metadata. Use identical checkpoint/seed and a recorded intervention.

The case directory contains `execution.json`, exclusive-create `process.log`, and producer outputs. A numerical case also retains `reference.log` and `reference-execution.json`. A successful prior case is reverified, never rerun blindly. A running/failed receipt or changed plan/source/input/output is rejected; preserve that candidate and obtain an explicit recovery/new external candidate-directory decision. No silent retry or automatic chain of campaigns. Commands must honor cooperative timeout/product cancellation; the enclosing Actions job has a 150-minute final bound. The harness never kills an MLX process mid-command-buffer.

## Actual producer receipt (not a mock success generator)

Each case's evidence JSON must contain `status:"executed"`, exact `sceneworks/inference`, `caseId/backend`, actual `hardware:{device,driver}`, and supporting case-relative `files`.

Successful model-execution cases (artifacts, capabilities, bounded-loading, cold-warm-staged) require `runtimeIdentity` and actual post-acquisition provenance; refusal/drift/preload-cancel and arithmetic tests instead provide `testInputSha256` matching a verified input, plus executed assertions. Do not invent a successful load for a refusal.

- `runtimeIdentity.checkpointSha256` matches the independently verified original checkpoint content. Include `planId`, `semanticDigest` (hex64), `topology`, `quantization`, `components:[{sha256}]`, `adapters:[]`, `operation`, `samplingPolicy`, and integer `seed` for paired interventions.
- `loadEvent` is the captured S10 tracing event, either its `fields` object or the enclosing JSON event. Exact names: `event:"h3_import_prepared_load"`, `jobId`, `provider`, `native_backend:"mlx"|"cuda"`, `backend` (actual device/job label, not the native runtime name; CPU is refused), `seal_validated:true`, `cache_state:"Cold"|"Warm"`, `identity` (JSON string/object with `checkpointId/planId/semanticDigest/assembly/sourceFiles:[{path,sha256}]`), `prepared_sources` (JSON string/array of `{path,sha256}`), `operation`, `seed`, `steps`, and `scheduler_shift` (current `Some(number)`/`None` tracing representation or structured number/null). Observed sampling values must match `runtimeIdentity.samplingPolicy:{steps,schedulerShift}`. The harness's terminal-only normalizer labels it **prepared-native-load-closure**. This event is emitted after successful generator acquisition and seal validation, including cache hits. It is not a claim that every sealed tensor was read; no per-tensor attestation gate or per-step rehashing is introduced.
- `completedJob:{id,status:"completed",providerId,output}` binds that observed native closure to the successful actual job/output. Artifact/capability `output` must match the AV evidence path. Retain original job/trace captures among supporting files. Source files, prepared components/adapters, plan identity, operation and seed must agree with independently verified inputs and runtime semantics. Producer normalization must preserve actual fields, not manufacture driver/provider/job identity.

For successful model-execution cases, `metrics` contains positive `hostPeakBytes`, `devicePeakBytes`, `loadHostPeakBytes`, `loadDevicePeakBytes` and `observations:{host,device,loadHost,loadDevice}`. These are **measured peaks with honest method labels**, not a requirement for an unavailable native allocator counter. Each observation contains:

- `method`: host `sampled-process-rss` or `os-rss-high-water`; device `sampled-process-cuda-used`, `sampled-device-used`, `sampled-native-allocated`, `native-allocated-high-water`, or `mlx-allocator-cumulative-high-water`. CUDA/MLX-specific methods must match that backend.
- `sampled` (boolean), `intervalMs` (positive for sampled methods), `samples:[{at:ISO8601,bytes}]` (at least two for sampled methods), and `blindspots:[string]` (nonempty for sampled methods). The scalar peak must equal the maximum retained observation, not a producer-invented summary. Sampled peaks can miss between-sample transients; disclose that limitation rather than claiming exact highwater.
- `window:{start:ISO8601,end:ISO8601,phase:"case"|"loading",coverage}`. Case coverage is `full-case`. Loading coverage is `full-case-load-inclusive` (a conservative whole-case bound is valid) or genuinely observed `native-loading-windows`. `h3_import_load_start` → `h3_import_prepared_load` covers source acquisition through provider-handle acquisition only; H3 defers TextEncoder/Renderer loading inside generation. That acquisition subwindow alone cannot masquerade as all-loading coverage.
- `attribution:{scope,meaning,pid?,deviceId?,includesOtherProcesses?,includesPriorAllocations?}`: give the actual metric meaning and process/device attribution. Device-global used-memory sampling is accepted with `scope:"device",includesOtherProcesses:true`; do not imply exclusive/process-only attribution. Process methods require an actual PID; device methods require device identity. MLX `allocatorPeakBytesCumulative` / `get_peak_memory()` and OS process highwater are process-lifetime counters, accepted only with `scope:"process-lifetime",includesPriorAllocations:true`, not relabeled as phase-local counters.

Pre/post committed residency deltas and individual CUDA `mem_get_info` snapshots are not peaks. An actual time series of device-used observations can prove an honestly attributed **sampled device-used peak**, not native allocation highwater. A device-global observation requires `bounds:["observed-device-global-bound"]` and certifies only that observed bound, never model-attributable allocation or per-process estimate accuracy. A whole-case load-inclusive observation requires `bounds:["full-case-load-inclusive-upper-bound"]`, never an exact loading-phase peak; include both labels when applicable. Separate host/device/loading observations remain separate; never sum unified-memory RSS/device allocations. No local GPU execution or new runtime admission/currency restriction is introduced.

Artifact/capability cases supply `av` (relative muxed media path). Artifact cases retain exact frozen `source/artifact`; capability cases supply `control:{av,checkpointSha256,seed,intervention}`. Both video and audio must have frames/duration and fully decode with ffmpeg `-xerror`.

Numerical cases supply `reference:{revision,sha256}` matching the pinned reference input, and `numeric:{candidate,reference}` relative numeric-array paths. They must execute at least one Rust test with zero failures/ignored tests. Generalization/lifecycle cases similarly require executed Rust tests, or `apiTranscript` produced by the API driver with actual completed observable assertions. Shape-only/hash-only receipts are insufficient.

### Sensitivity, lifecycle and observation boundaries

For every capability representative, retain baseline B0, unchanged repeated baseline B1 and intervention I with the same actual checkpoint/native closure, seed and full sampling/geometry/config. Predeclare a meaningful RMSE minimum T and maximum permitted repeat noise N **before** outcomes. Execute the existing harness's CPU media comparison command on actual job outputs:

```sh
node scripts/h3-finetune-terminal.mjs compare-control "$B0" "$B1" "$INTERVENTION" audio "$T" "$N"
```

Use `video` for visual interventions and `audio` for audio-reference reorder/drop/change; the generated comparison manifest records each stream separately. Both AV streams fully decode. The comparator requires repeat RMSE ≤ N and intervention RMSE > max(T, 3×repeat RMSE); unchanged output, container-only/hash changes, sub-threshold effects and noisy nondeterministic baselines fail. It returns media identities and observed deltas, **not** proof of model provenance. Bind all three actual load events/completed jobs/source closures separately; a producer-supplied checkpoint label is insufficient. The API interpreter records requests/assertions but does not automatically execute the `comparisons` manifest. Retain comparison JSON in existing supporting evidence and inspect all mechanism subcells, not just the first control.

Lifecycle runtime boundaries are explicit, not new magic routes:

- Restart only task-owned service/worker state through its existing process lifecycle, preserving the disposable data directory. Record pre/post process identities and the persisted original job, then run the prepared `/duplicate` scenario; replay must preserve selected model, seed/recipe, source/component lineage and asset provenance. There is no `/restart` API.
- Source drift mutates **only a private copied checkpoint**, before normalization and under a provider lease; use the existing worker `source_mutation_before_or_during_normalization_cannot_publish` and core `h3_interruption_retry_drift_relink_duplicates_and_leases_preserve_ownership` programs. Refusal must precede load/publish; don't claim model execution. Relink uses PATCH `/models/library-roots/{id}` with `{path:newOwnedRoot}`; rescan uses POST `…/{id}/rescan` with `{relativePath}`. Recompile against actual new bytes and compare saved semantics. No mutation of linked originals/shared caches.
- The cancel scenario must catch a queued/in-flight **owned** import. If it finishes before cancellation, that's an unresolved missed observation, not cancellation evidence. Existing crash-orphan/transaction fixtures cover dropping an unfinalized ingest; an actual interrupted-service run needs its real process/orphan records, not a fabricated HTTP interruption action. Retry only that owned import. Native GPU cancellation remains cooperative, never kill mid-buffer.
- For removal/leases/duplicates, retain actual managed/linked inventory and before/after **owned** source bytes. The focused derivative/plan-store fixtures enforce ownership/lease behavior; app removal's 200 alone does not prove that a linked original survived. Managed/linked outputs additionally use the same-seed repeated-baseline bound, not file equality across nondeterministic backends.
- Cold/warm/staged cases require actual observed cache state/staging configuration and native closure. Labels alone do not establish a cold cache. Never clear shared state to manufacture coldness.
- Host observations can use `/bin/ps -o rss= -p "$OWNED_WORKER_PID"` (KiB→bytes) on macOS or `Get-Process -Id $OwnedWorkerPid` `.WorkingSet64` on Windows, sampled across the whole case with actual PID/timestamps/cadence. CUDA can sample `nvidia-smi --query-compute-apps=pid,used_gpu_memory --format=csv,noheader,nounits` with actual PID, or `--query-gpu=uuid,memory.used --format=csv,noheader,nounits` as **device-global**, including other processes. Check availability before selecting a method. MLX's `allocatorPeakBytesCumulative` remains **process-lifetime**. Sampling gaps/missing process rows are not zeros. Separate host/device peaks; retain whole-case load-inclusive upper bounds unless all deferred loading windows are actually observed. Analytical profile facts live in `gen_core::h3_memory::NativeAllocationFacts`: actual methods are `precompute_peak_bytes(rows)`, `denoise_peak_bytes(rows)`, `precompute_peak_bytes_windowed(...)`, `denoise_peak_bytes_windowed(...)`, `resident_peak_bytes_windowed(...)`, and `peak_bytes(rows)`; window allocation has its own resident/precompute/denoise methods. Record these as analytical storage/scratch/stage bounds, never measured peaks or residency-delta substitutes. Existing `h3_terminal_telemetry::Collector` samples host RSS every 40 ms plus step completion, but covers the **denoise observer lifetime only**; it cannot prove full loading/case coverage. Its device values are backend allocator/pool cumulative highwater, not a Veda-only or isolated per-step peak. Normalize only actual available fields and preserve null/unavailable values; obtain full-case loading coverage separately.

### Exact remaining interface constraints

There is no invented `produce-terminal-evidence` command. Existing native fixtures assert structured embedded outputs internally, but do not export the terminal harness's flat candidate/reference arrays. Regenerated external JSON must match the embedded fixture at the stationary pair; otherwise do not run a stale compiled oracle or hand-edit expected values. Existing API scenarios emit actual transcripts but do not emit a complete native-load/measurement receipt. Capturing/normalizing actual trace/job/AV paths, all baseline/intervention closures, subcell comparisons and sampler observations into the existing schema is still required before terminal proof. Neither HTTP-only app integration nor raw-engine-only generation may masquerade as the other.
