The data directory contains an explicit prepared `s9-workspace-owner.json` equal to `{campaignId,sourceFreezeSha256:sha256(canonical(sourceFreeze)),projectId}`. Config staging must contain the exact byte-identical source catalog manifests. Startup refuses stale/dirty source, wrong binaries, foreign workspace, unbound source or occupied listener. Guardian/API authentication secrets are not written into evidence; `SCENEWORKS_TOKEN` is required at runtime. A private0600 control file carries the task IPC token, not an API secret.

The adapter launches a detached task-scoped guardian and authenticates live local IPC with its random owner token and complete manifest fingerprint. It resumes only that exact live owner, or a verified closed receipt with services drained, token hash/pid/fingerprint identity and prior owner exit. A refused/dead IPC response never proves absence of an old physical owner. The guardian directly starts the source-attested ordinary API binary and same worker-entry binary with `SCENEWORKS_WORKER_ONLY=1`, isolated `SCENEWORKS_DATA_DIR`/jobsDB/config/port, `SCENEWORKS_API_URL`, access token and `SCENEWORKS_PARENT_PID=<guardianPID>`. CPU utility routing stays CPU. It never invokes a native test/example generator. Worker selectors are explicit mlx or the selected physical CUDA index, never auto. CUDA_VISIBLE_DEVICES is the exact locked UUID (engine ordinal0); NVIDIA_VISIBLE_DEVICES preserves its source-proven physical index for normal worker discovery.

Root-owned API/worker processes inherit the actual lock descriptors, so guardian death does not release flock until inherited owners exit; the normal product's parent watchdog points at the guardian. Normal cleanup drains only the owned process groups and verifies no same-group descendants remain before closing locks. Normal API/worker roots start suspended, are assigned to non-breakaway KILL_ON_JOB_CLOSE jobs and then resumed; assignment failure kills/reaps only that suspended owned child. Cleanup terminates/reaps the entire owned job before lock close. An incompatible enclosing Windows CI job is a refusal.

## Durable submission and controller loss

Before enqueue the JS driver atomically persists `submitting`, key, full request digest and request. It invokes the guardian's `submit` method. The guardian validates current physical ownership, fresh phase/queue admission, the source fingerprint and exactly one matching durable intent, fsyncs its own journal, starts/validates only the normal owned worker, and performs the ordinary **POST `/api/v1/video/jobs`** itself. It durably records the returned product job ID before responding over IPC. This covers controller SIGKILL during POST and response loss. A failed acknowledgement that provably never issued POST is recorded as `not_submitted`; a transport failure after POST remains ambiguous. Duplicate acknowledgement cannot erase an existing job or reenqueue it.

Controller PID/birth loss, retained uncertainty or maximum deadline causes the independent guardian to reconcile/cancel only guardian-acknowledged ordinary jobs, read back terminal status, drain/reap only its API/worker tree and recheck actual physical baseline before unlock. Foreign job IDs, project identities or marker mismatches are never canceled. Missing/duplicate/full history, unreachable API or incomplete descendant reaping cannot authorize unlock. Cleanup is bounded; if persisted queue uncertainty remains after services are drained, the guardian writes an explicit blocked receipt and retains its physical descriptors for owner reconciliation rather than fabricating safety. It performs no repeated render/reconciliation campaign in that blocked state. The blocked lock holder is a deliberate fail-closed state, not completed acceptance. Subsequent startup preserves old journal intents and will not start a GPU worker while an unresolved prior intent could replay.

Actual product/OS process crash behavior, especially Windows native handle semantics and Mac inherited-descriptor/watchdog exit, still requires the coordinator's pre-campaign operational proof under the exact permanent source/binary freeze. These CPU fakes do not constitute generated media, native hardware acceptance or Michael's quality decision. Per-step/host-device peak telemetry is independently owned and untouched here.
