## Ordinary product transport and ownership

The flat video DTO is submitted to **POST `/api/v1/video/jobs`**. First frame uses `sourceAssetId`, last frame `lastFrameAssetId`, image references `referenceAssetIds`, clips `sourceClipAssetIds`, standalone audio `referenceAudioAssetIds`. GET `/api/v1/jobs/:id` supplies durable status; GET `/api/v1/jobs/:id/metrics` supplies observed metrics. Output asset content is obtained through the ordinary project asset/file routes. Generic POST `/api/v1/jobs` is not the video route.

Before execution, the coordinator supplies a byte-bound **current-source physical guard adapter** and freezes its source hash in `sourceFreeze.files`. Default `run` fails closed when this adapter is unavailable. An admission JSON and the campaign resume marker cannot authorize GPU work. The adapter exports `protocol="epic-25140-physical-guard-v1"` and `acquire({manifest,backend,runDir})`; it must acquire/hold the existing combined Mac GPU/nax flock token or Windows selected-UUID exclusive OS lock, not a new independent file lock. `sourceFreeze.resourceContract[backend]` binds `{physicalGpuId,canonicalLocks}` to those exact established lock identities. Root supplies that actual OS-backed adapter before terminal execution; the example deliberately leaves it unbound.

The acquired live external guard exposes `{owned,ownerToken,lockIdentities,isOwnerAlive(),ownsCanonicalLocks(),beforePhase(phase),retainForOwnedJobs(intents),release()}`. Before each phase admission, the guardian reads back any completed owned job, reaps the owned worker and API process trees, restarts the same byte-bound normal API against the same private data/config/project, and checks its authenticated readiness. The phase receipt includes the prior API PID/birth, exact API binary hash and reaped-descendant proof; collection also preserves the job-bound worker incarnation. A dead or ambiguously drained API cannot authorize another phase. The restarted API is included in the ordinary physical probe, so a compute context in that process still causes the unchanged pure-compute refusal. This rotation closes a process-lifetime gap; it does not establish that the previous API actually created a GPU context.

`beforePhase` performs fresh existing driver/queue admission and returns `{phase,ownerToken,admitted,physicalGpuId,observedAt,queueObservedAt,conflictingJobs,driverSamples,drainedApi}`. Exactly five increasing-time driver samples require `{observedAt,admitted:true,driverAvailable:true}`; phase/queue evidence must be within10s and driver samples within15s. These are outputs from the current verified actual guard adapter, not an opaque receipt supplied as a substitute. Calls occur at campaign start and before carrier preparation, submit/reconcile and completed-evidence collection. Wrong lock, unowned/dead owner, stale phase, conflicts or missing samples are refused. The external holder must retain ownership for all ambiguous/active owned intents until reconciliation/cancellation, even if this controller exits. `retainForOwnedJobs` handles that case; process exit alone must never free the physical token while a worker might still render.

`leasePath` is only an exclusive **campaign resume marker**. A dead marker owner may resume only its own exact campaign/run-directory/fingerprint; foreign/live markers are refused. It neither replaces nor claims the physical OS lock. The source-owned adapter/guardian is implemented. Exact native process/OS/device operational proof remains required under the permanent freeze; CPU tests prove driver refusals and synthetic process/journal ordering only.

The manifest's finite `maxJobs` bounds each invocation without pruning the matrix. Intent, full request digest and `advanced.s9Harness` identity are persisted before enqueue. Successful job ID is persisted immediately. Ambiguous transport reconciles via `/api/v1/jobs?projectId=...&limit=500`; absent, duplicate, changed or full-window results cannot justify resubmission because the API has no enqueue idempotency or complete history pagination. The lease remains held when any owned job may still be active. Timeout cancels only the owned job and reads back its terminal status. Cleared/unknown jobs require explicit reconciliation; the driver never guesses that they were not delivered. Resume revalidates source/input identity and hashes collected outputs, never automatically rerenders failed/gapped arms.
