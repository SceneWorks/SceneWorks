## Style-set calibration (public corpora, pulled 2026-07-27)

Pulled 4 public style sets via the HF datasets-server (112 images):

```

WeirdOutfitStyle           40    0.2932   0.9796         1
PaperCutoutStyle           14    0.3514   0.9141         0
cartoon-blip-captions      40    0.4645   0.9720         1

pooled: 1804 pairs — >=0.90: 10 (0.6%)  >=0.95: 2 (0.1%)  >=0.99: 0
```

**Style floor (0.10) is confirmed safe but close to inert.** Every set lands
0.265–0.465 — none would flag at any floor up to 0.20. Combined with the two
prior samples (0.144, 0.284) the style corpus is now 6 points spanning
0.144–0.465, median ≈0.29. At 0.10 the floor can only catch pathological
uniformity (e.g. 20 crops of one painting). Raising it to ~0.14 would still
clear 5 of 6 observed sets; whether that's desirable is a product call, not a
data one.

Secondary observation: style sets are far less near-dup-dense than person sets
(0.6% of pairs ≥0.90 vs **17.0%** for the person corpus). Expected — a person
set is many shots of one face; a style set deliberately varies subject. Confirms
`near_dup_cosine` needs no kind-specific split.

## Caption-alignment calibration (58 captioned pairs)

`sweep_caption_alignment` did run after all — the HF rows carry a `text` column,

```
0.15    5/58   (9%)   <-- CURRENT     1386/1440 (96%)

```

`CaptionAlignmentThresholds::default().cosine_floor` is **0.15**
(`dataset_quality.rs:1517`) → **9% of correctly-captioned images flag** on this
corpus. 0.12 gives 0% false positives and still catches 86%.

**Do not act on this without a second corpus.** Two caveats:
1. These captions are terse tags ("A planet, yarn art style"), not the JoyCaption
   "Descriptive/long" prose the 0.15 floor was calibrated against — that
   calibration cites matched min ≈0.18, where mine is 0.1345. A weaker matched
   distribution inflates false positives at any floor, so some of the 9% is
   corpus artifact.
2. FULL CAPTION and FIRST SENTENCE returned **identical** numbers, because these
   captions are already single sentences. So this run cannot validate the
   first-sentence reduction that the check's design depends on.

The actionable next step is re-running this sweep over a JoyCaption-captioned
set — which SceneWorks can generate itself, since it auto-captions.
