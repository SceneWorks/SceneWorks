# Round 7 adversarial review of Shared Generation Architecture draft 0.6

November 7, 2026 · **Verdict: revise before planning.** The first runner contract, first proof cohort and first memory consumer all have counterexamples in the shipped sources. Encoding the current roadmap as tracker dependencies would make several feature exits impossible or permit a regression to pass acceptance.

Reviewed the README, requirements, roadmap, previous dispositions and supporting research at `78d75afde7a521e1edf3850fdfb6be15083d90e7`. Compared the contracts to SceneWorks main at `e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8` and its exact inference pin at `2b09938e33370915d4f853389961709b8bbf8bf9`, which also matched inference main. The earlier round 6 verdict covered four prior findings on draft 0.5. This review asks whether draft 0.6 can govern delivery on the current product. Confidence is **high** in the source contradictions and missing acceptance conditions. Performance, output quality and the cost of implementing the remedies remain unmeasured. ## Blockers before feature planning

### B2. The immutable pass list cannot describe a shipped data-dependent route

SenseNova interleave generates text until the model emits an image-start token, an end token, or reaches its budget. Each generated image is fed back into the conditioning cache before text generation resumes. The same request limits permit zero, one or several images. PIPE-1/2 compile the complete run before loading. The runner iterates a fixed pass list, and a family driver's documented interface receives a denoise slice and returns a boundary latent. Neither specifies who conditionally invokes the next image stage and re-encode, how its memory is admitted, or how an early finish is reported. Repeated output delivery alone cannot perform that feedback step. [PIPE-1/2](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L147) · [RenderPlan and PassPlan](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L155) · [FamilyDriver](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L339) · [Token-dependent dispatch](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-sensenova/src/t2i.rs#L1700) · [Generated-image feedback](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-sensenova/src/t2i.rs#L1786)

**Closure.** Specify a bounded conditional stage or a typed native-driver operation with explicit ownership of nested stage execution. The pre-load plan can commit to token/image/geometry limits and a conservative budget. The run report records the path actually taken. Trace zero images, two images with re-encode between segments, early termination and cancellation, including existing progress semantics. This establishes the runner boundary before ENG-1a freezes it.

### B3. The proposed provider traits impose a thread-safety contract the live system does not have

Both family traits require `Send + Sync`. Today's `Generator` has no such supertraits. SceneWorks serializes generator work on an owning thread. H3 keeps Metal kernel handles thread-local, PuLID constructs a non-sendable scorer on the generator worker, and InstantID uses global MLX seeding. Two requests with different seeds can interfere if the runner allows a reseed between the first request's seed and draw. The proposed mock interleaving test checks phase scales and cannot establish native RNG or device-thread safety. [Dispatch bounds](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L312) · [PIPE-14 acceptance](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L256) · [Actual trait](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/contracts/gen-core/src/generator/traits.rs#L5) · [Serialized worker](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/crates/sceneworks-worker/src/generator_cache.rs#L589) · [PuLID scorer](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/crates/sceneworks-worker/src/image_jobs/pulid.rs#L570) · [Metal thread affinity](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-minimax-h3/src/veda/metal.rs#L456) · [Global seed and draw](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-instantid/src/model.rs#L1100)

**Closure.** Separate thread-safe registration and request messages from thread-bound loaded state. Specify which executor owns load, forward, cancellation, destruction and poisoned-state recovery. Make overlap opt in per proven provider, or serialize trajectories that require it. Require an owning-thread mock and a two-seed trace that interleaves or queues according to the declared policy. Include the existing worker entry point in the separately dispatched proof when its execution behavior changes.

### B4. The first pricing example assumes evidence the first shipping cohort does not provide

The plan's arithmetic is valid when a measured operation's coverage is known. The FLUX.1 Candle evidence explicitly says that conditioning, denoise and decode fields repeat a single whole-request high-water. It covers q4, 1024², batch one, base text-to-image. It does not establish the cost of a 512² phase, an endpoint evaluation with retained buffers, or an adapter overlay. Copying the value from a field labeled “denoise” into a per-operation calculation creates unsupported precision. Falling back to a route's ordinary unpriced posture can admit a new recipe without satisfying ENG-1b's conservative bound, or refuse the entire first cohort. [Pricing basis and fallback](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L559) · [ENG-1b first consumer](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L577) · [Certified coordinates](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/docs/flux1-candle-memory-ladder-sc-15823.md#L5) · [Meaning of repeated phase peaks](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/docs/flux1-candle-memory-ladder-sc-15823.md#L33) · [ADM-3](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L572)

**Closure.** Work one first-wave FLUX.1 example using an actual evidence identity, covered operations and byte units. Show a defensible upper bound for the new transition, including what the existing total already covers. Test exact-fit, one-byte-under and unknown coverage. Keep the old route's posture, and give the new recipe an explicit disposition if its incremental peak cannot be bounded. Reuse source-derived bounds or the already planned bounded proof. No calibration grid is needed.

## Major findings

### M1. The job snapshot mixes portable intent with machine-local authority

APPREG-6 prohibits re-resolution of the captured spec. The runtime layer includes converted paths, install state and credential projections. In production the worker resolves its local library for the requested variant, validates paths, acquires leases and can reject a partial materialization. A snapshot created on a Mac cannot establish what is installed on a CUDA worker. The same boundary matters for imports. Server policy currently checks protected repositories, selected components and inherited acknowledgments even when author-provided flags say otherwise. The words “one merge rule” do not define precedence for those fields. [APPREG-1/6](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L483) · [Snapshot contents](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L619) · [Worker-local binding](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/crates/sceneworks-worker/src/external_library_runtime.rs#L99) · [Path checks](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/crates/sceneworks-worker/src/external_library_runtime.rs#L1011) · [Inherited component authority](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/rust-api/src/models/license.rs#L415)

**Closure.** Define the immutable logical source/variant identity, permitted user overrides, server-owned policy fields, and worker-local binding. State what is persisted, sent, and redacted. Test a retry on another host with a different root, an unavailable artifact, a reused alias pointing to changed bytes, and an imported overlay trying to clear a protected component. Preserve safe refusal before any disallowed fetch or load.

### M2. Replay permits a silent recipe change in two independent ways

ENG-1b puts low-res data through the existing share path. A v1 reader drops unknown fields. It can accept a v1 envelope carrying a result-changing recipe and reproduce ordinary generation. Separately, PIPE-11/FEAT-1 promise deterministic replay while admission can newly select an equivalent feature with bounded pixel differences. The cited regenerate code strips `advanced.memoryStrategy` from an asset recipe, and the duplicate-job path normally supplies fresh randomness. Regenerate, exact replay, and importing a portable recipe have different observable behavior today. [First share writer](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L763) · [Seed contract](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L238) · [Equivalent Features](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L441) · [Old-reader behavior](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/docs/workflow-share-envelope.md#L136) · [Asset cleanup](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/web/src/regenerateImage.js#L28) · [Duplicate behavior](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/web/src/regenerateImage.js#L113)

**Closure.** Define each operation and the identities needed for promised fidelity. Have a real old reader reject an unrepresentable active recipe while continuing to read ordinary v1 shares. Exercise same-backend replay when the original quality-affecting rung no longer fits. Decide whether exact replay refuses or the caller explicitly accepts an approximate result. Preserve the existing regenerate action's seed behavior.

### M3. The first img2img phase has no defined input construction

The low-res example defines the transition at K in detail. For an actual img2img route it only resolves strength and step truncation. Encoding resized source pixels at phase-one dimensions and encoding at full resolution then resampling normalized latents produce different inputs, peak allocations and images. FLUX.2's shipped implementation resizes pixels, encodes, crops, matches the latent grid and normalizes. Both proposed interpretations can satisfy the current final-size and deterministic replay checks. [Worked example](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L803) · [FEAT-1 parameters and modes](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L687) · [Live init construction](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-flux2/src/model.rs#L885)

**Closure.** Specify which grid owns initial pixel fit, codec encode, normalization, seed/noise blend and rounding. Trace a non-square source at non-unit strength over two legal grids, distinguish init-image conditioning from identity/control references, and include initial encoding in the admission bound. Version the selected behavior with the recipe.

### M4. Training can pass acceptance with the wrong backward pass

ENG-8 deletes training graph copies. WGT-4's acceptance checks that they disappeared. The proof set lists generation routes, and the risk register merely puts trainers in Tier 1. Correct forward output can coexist with detached adapters, zero gradients or a broken optimizer/checkpoint resume. The pinned FLUX.3 tree already has gradient/optimizer and checkpoint oracles. Waiting for the optional ENG-15 pilot would expose the regression several features late. [WGT-4](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L401) · [ENG-8 exit](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L985) · [Training risk](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L1103) · [Gradient and optimizer reference](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/mlx-gen/mlx-gen-flux3/tests/training_parity.rs#L40) · [Checkpoint tests](https://github.com/SceneWorks/inference/blob/2b09938e33370915d4f853389961709b8bbf8bf9/crates/media/candle-gen/candle-gen-flux3/tests/training_checkpoint.rs#L1)

**Closure.** Give each affected trainer a bounded old/new backward and resume witness at the feature removing its graph. Compare expected trainable/frozen sets, gradients or update deltas, and resumed versus uninterrupted next update. Use existing fixtures and separately dispatched learned execution. A render alone cannot close WGT-4.

### M5. The H3 proof can pass while the shipped 24 GiB route regresses

The SGA proof set names H3 T2VA as a two-schedule driver. Since the design freeze, SW-F329 delivered a specific 1344×768, 345-frame, q4 CUDA case using both text-encoder and DiT windows. The accepted comparison controlled sparse execution, allocator and workspace policy. A short default render, or a forced-dense comparator, can succeed after breaking the long sparse route. A same-host A/B alone does not control these conditions. Fidelity and performance comparisons should pin effective tier, adapters, schedule, allocator/workspace policy, warm/cold state and device. Report an inconclusive comparison when these differ.

### M6. The proposed UI baseline can freeze an earlier regression into the expected result

Test menu selection, submitted batch prompts, imports and meaningful sampling overrides through public UI/request paths. Tie the zero-removal result to the baseline revision.

### M7. The same desktop binary is both API and worker

LANE-6 requires that the API Cargo graph exclude worker lanes while retaining desktop worker mode. Today the API executable is relaunched in worker-only mode, performs GPU preflight, and re-enters for Iris training ranks. Its manifest links the worker. Moving validation to core does not by itself change that binary graph. A dependency test interpreted at package scope could fail the shipping build, or pass on a feature combination that desktop never ships. [LANE-6](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/REQUIREMENTS.md#L596) · [Proposed end state](https://github.com/SceneWorks/SceneWorks/blob/78d75afde7a521e1edf3850fdfb6be15083d90e7/docs/architecture/shared-generation-architecture/IMPLEMENTATION_PLAN.md#L712) · [Worker dependency](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/rust-api/Cargo.toml#L33) · [Rank and worker entry points](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/rust-api/src/main.rs#L66) · [Desktop launch](https://github.com/SceneWorks/SceneWorks/blob/e1ffa54df69a6d37b9efaa61f8a6dbce9d279ff8/apps/desktop/src/setup.rs#L2347)

**Closure.** Name the API-only and desktop composition roots, the unit on which the dependency rule is asserted, and which binary the desktop bundles. Preserve worker-only launch, preflight, rank re-entry and supervision in the packaging acceptance. An API-library dependency check and a desktop launch check answer different questions.

### M8. REG-3 needs an explicit distinction between a product schema and pin-currency verification

REG-3 demands a regenerated, checked-in export at each pin and Tier 0 equality with the linked registry. The repository's teardown explicitly removed pin-driven capability invalidation. A deterministic hardware-free product schema can legitimately change when its semantic contents change. Treating an unrelated pin movement as requiring a new receipt or measured dump would restore the retired gate. The plan's hosted-Candle fallback also puts a CUDA host on the critical path if the hardware-free build fails, while the requirement still mandates hosted, hardware-free generation. ### M9. The iOS proof omits the comparison that protects its admission behavior

### M10. A bounded pass list does not yet bound a submitted job's total work

FEAT-2 bounds list length. It also composes with native multi-pass recipes, count, step overrides, solver sub-evaluations and optional endpoint forwards. ### M11. Shared output finalization lacks a failure and retry contract

The new generation lane ends with separate write and stamp steps. PIPE-15 specifies GPU cleanup and host claim release, while PIPE-16 tests chunk backpressure and ordering. Neither defines what becomes visible when the worker fails between publishing assets and committing the job receipt. SenseNova already writes a sequence of images, builds an ordered document referencing them, and writes that document separately. A cancel, lost worker or retried attempt between those operations can leave partial artifacts or two terminal results unless the shared lane inherits the current store's ownership rules. ### M12. Fidelity and timing have conflicting pass criteria

AP3 compares a disabled Feature to “today” and requires byte identity. AP13 allows an approved component-tolerance migration. Its measured-noise exception has no stated procedure for telling an inconclusive comparison from a pass.
